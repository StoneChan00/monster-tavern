# 《魔物酒馆》Monster Tavern · 挂机经营游戏 · 方案与前置需求

> 正式名称：**《魔物酒馆》（Monster Tavern）**
> 文档版本：v0.2（立项决策已全部确认，见第 8 章） · 状态：已立项，待进入 Phase 0
> 项目根目录：`monster-tavern/` · 决策确认日期：2026-09-21

---

## 1. 项目概述

### 1.1 一句话定位

一款**网页端 2D 像素风挂机经营 RPG**：玩家扮演酒馆老板，招募冒险者组成队伍自动下地牢刷魔物，用魔物材料升级酒馆、烹饪魔物菜肴，菜肴既强化冒险者又吸引更强的冒险者慕名而来。

### 1.2 核心幻想（Core Fantasy）

> "我不去冒险，冒险因我而来。"

玩家不是冒险者，而是冒险者背后的那个人——酒馆的灯永远亮着，炖锅里咕嘟着魔物浓汤，墙上挂满了冒险者送来的战利品。你配置好队伍，他们替你下地牢；你端出好菜，强者慕名而来。

### 1.3 设计支柱

| 支柱 | 含义 | 反例（避免） |
|---|---|---|
| 配置即玩法 | 玩家的核心操作是"决策"（编队/做菜/升级），而非操作战斗 | 需要实时操作才能推进 |
| 离开也有收获 | 关掉网页，冒险者仍在地牢里为你打工 | 必须挂机在线才有效益 |
| 材料有去向 | 每种材料都指向明确用途（基建 or 菜肴） | 背包变成垃圾堆 |
| 美食即成长 | 菜肴系统连接"战斗产出 → 阵容成长 → 招募"三条线 | 菜肴只是数值兑换所 |

### 1.4 平台与形态

- **平台**：浏览器（桌面优先，兼容移动端浏览器自适应布局）
- **数据**：全部存放在用户本地（localStorage / IndexedDB），无后端、无账号
- **画风**：2D 像素风，**Kenney Tiny 系**（16×16、2px 粗轮廓，已确认）
- **发布**：**itch.io 为正式渠道**；GitHub Pages 作为早期演示页（两者均为纯静态部署：itch.io 上传 zip 即可，GitHub Pages 走 Actions 自动部署）
- **付费**：无内购（本地单机）

## 2. 游戏设计

### 2.1 核心循环（三层结构）

```
┌─ 短循环（秒~分钟）────────────────────────────┐
│  队伍自动战斗 → 掉落金币/材料/经验 → 背包累积   │
└──────────────┬───────────────────────────────┘
               ▼
┌─ 中循环（分钟~小时）──────────────────────────┐
│  材料分配决策：                               │
│   A. 升级酒馆设施（宿舍/厨房/训练场…）        │
│   B. 烹饪菜肴 → 冒险者 buff + 吸引新冒险者    │
│  → 队伍变强 → 推进更深层地牢 → 更好的掉落     │
└──────────────┬───────────────────────────────┘
               ▼
┌─ 长循环（小时~天）────────────────────────────┐
│  解锁新地牢生态（新材料/新菜系/新魔物图鉴）    │
│  冒险者忠诚/传承、声望等级、（后期）转生       │
└──────────────────────────────────────────────┘
```

挂机游戏标准节奏框架：**赚取 → 花费 → 加速 → 碰墙**。碰墙（当前层数打不过去）驱使玩家优化配置，是设计好的停顿点而非挫败。

### 2.2 冒险者系统

#### 职业（MVP 6 职）

| 职业 | 定位 | 战斗行为 | 偏好菜肴（吸引类型） |
|---|---|---|---|
| 战士 | 坦克/前排 | 承伤、护盾 | 烤肉类硬菜 |
| 法师 | AOE 输出 | 群体法术 | 精致甜点/魔素料理 |
| 盗贼 | 单体爆发 | 高暴击点杀 | 刺激小食 |
| 牧师 | 治疗 | 持续回复 | 清淡汤品 |
| 游侠 | 持续物理输出 | 后排速射 | 野味烧烤 |
| 吟游诗人 | 全队增益 | buff 光环 | 果酒/饮品 |

> 职业 × 菜肴偏好是本作的核心差异化设计：**菜肴系统同时是养成系统和招募系统**。

#### 属性与成长

- 基础属性：`HP / ATK / DEF / SPD` + 职业属性（牧师治疗量、盗贼暴击率等）
- **稀有度**：普通（白）/ 优秀（绿）/ 稀有（蓝）/ 史诗（紫）/ 传说（橙）——影响基础属性倍率（1×/1.3×/1.7×/2.2×/3×）和被动技能数量（0/1/1/2/3）
- **等级**：战斗获取经验；等级上限 = 10 + 训练场等级 × 5
- **忠诚度（0~100）**：用餐、休息提升；战斗失败、长期不进食下降。高忠诚给属性加成（最高 +15%），忠诚归零冒险者离店
- MVP 阶段不做装备系统（后置），用"星级"（吃同名/同职业冒险者卡升星）替代简化

#### 招募（已确认：纯到访招募，无抽卡）

- 冒险者**自动到访**酒馆（每天固定若干批），到访池的稀有度权重由三个因素决定：
  - 酒馆声望等级
  - 已解锁菜肴对该职业的吸引力加成
  - 酒馆装饰/氛围值
- 玩家用金币+材料"签约"到访者 → 进入替补席
- 不设任何抽卡/卡池机制——"强者因美食与声望而来"是核心幻想的一部分
- 替补席上限 = 招待区等级（MVP 上限 10 人）

#### 队伍编成

- 3~5 人小队（随声望解锁第 4/5 席位），**前中后排**站位：
  - 前排：受击优先级高（战士）
  - 中排：标准
  - 后排：受保护（法师/牧师/游侠）
- **羁绊（简化版阵型增益）**：特定职业组合触发小队 buff（如 战士+牧师 =「坚守」+10% 防御；3 职业各异 =「杂牌军」+8% 掉落）——参考 Idle Champions 的阵型增益但大幅简化为组合规则，无位置朝向计算

### 2.3 地牢系统

#### 结构

- 地牢按**层（Floor）**推进：每层 5 波魔物 + 1 个层底 BOSS
- 击败层底 BOSS → 解锁下一层；已通关层数可自由设置**驻farm层**（挂机默认在能稳定通关的最高层循环）
- 层数 × 生态主题：1-10 层「苔藓洞窟」（史莱姆/蝙蝠/蘑菇怪）→ 11-20 层「骸骨墓穴」→ 21-30 层「熔岩矿道」……每 10 层换一套魔物/材料/色调

#### 战斗模拟（数值驱动，无操作）

- 回合制自动战斗：按 SPD 排行动序，坦克嘲讽、治疗过量转为护盾等规则
- 战斗在模拟层以纯函数结算（详见 3.4）；**MVP 阶段前端只做数值面板展示**，简单战斗画面（PixiJS 轻量视口）已确认为 Phase 2 目标
- **全灭保护**：队伍团灭 → 撤回酒馆休整（30 分钟受伤 debuff），不损失任何永久资源。挂机游戏永远不惩罚离开

#### 掉落表（加权随机）

每次击杀：金币（保底）+ 1~3 份材料（按魔物类型加权）+ 小概率菜谱碎片/稀有材料。层底 BOSS 必掉稀有材料 + 声望。

> 掉落采用**加权表**而非固定概率：新增物品时自动归一化，便于平衡。

### 2.4 材料系统

材料分两大类，确保"材料有去向"：

| 类别 | 例子 | 来源 | 主要去向 |
|---|---|---|---|
| 基建材料 | 魔物甲壳、硬化皮革、秘银矿 | 结构系魔物 | 酒馆升级/扩建 |
| 食材材料 | 史莱姆凝胶、蝠翼、火蜥蜴尾巴 | 生物系魔物 | 菜肴烹饪 |
| 稀有材料 | 深渊魔核 | 层底 BOSS | 高级菜谱 / 星级突破 |

材料价值随层数 ×1.08/层 增长（低于魔物强度的 ×1.15/层，制造"投资跟不上产出"的良性压力）。

### 2.5 菜肴系统（本作核心差异化）

#### 烹饪流程

```
解锁菜谱（地牢掉落/酒馆等级/声望）
  → 投入食材材料 + 金币 + 烹饪时间（15min~8h，实时计时，离线也推进）
  → 出餐 → 存入菜单（可同时生效 N 道，N = 厨房等级）
```

#### 菜肴双重效果

1. **战斗加成**：全队 ATK/DEF/经验获取/掉落率等 buff，不同菜系覆盖不同增益
2. **吸引力加成**：每道已解锁菜谱提升对应偏好职业冒险者的到访权重与稀有度权重（如「巨兽烤肉」解锁后，战士到访率 +20%，到访战士出蓝以上概率 +10%）

#### 菜系规划（MVP 10 道菜起步）

| 菜系 | 增益方向 | 吸引职业 |
|---|---|---|
| 烧烤系 | ATK | 战士/游侠 |
| 甜点系 | 法术强度 | 法师 |
| 汤羹系 | 治疗/HP | 牧师 |
| 小食系 | 暴击/SPD | 盗贼 |
| 饮品系 | 全队轻量增益 | 吟游诗人 |

### 2.6 酒馆升级树

| 设施 | 效果 | 消耗 |
|---|---|---|
| 招待区 | 替补席上限、到访者批次 | 金币+基建材料 |
| 厨房 | 同时生效菜谱数、烹饪速度 | 金币+基建材料 |
| 宿舍 | 休整速度、忠诚度增速 | 金币+基建材料 |
| 训练场 | 冒险者等级上限、离线训练效率 | 金币+基建材料 |
| 酒窖 | 饮品类 buff 强度（第二菜品线） | 金币+稀有材料 |
| 情报网 | 显示各层掉落预览、解锁深层地图 | 金币+声望 |
| 装饰 | 氛围值（全到访权重） | 金币+任意材料 |

升级造价：`cost(n) = base × 1.12^n`，每 10 级设里程碑质变（如宿舍 10 级：休整速度 ×2）。

### 2.7 经济系统

| 货币 | 获取（水龙头） | 消耗（下水道） |
|---|---|---|
| 金币（软通货） | 战斗掉落、完成任务 | 冒险者日薪、酒馆维护、菜谱购买 |
| 材料（多资源） | 战斗掉落 | 酒馆升级、烹饪 |
| 声望（进度货币） | 首杀层底 BOSS、稀有菜谱首做 | 情报网解锁、编队席位 |

- 日薪机制：冒险者每天结算工资（按稀有度），形成金币持续性支出，防止金币无限堆积
- 所有成长消耗曲线统一 `base × growth^n`（growth：基建 1.12 / 冒险者投资 1.15 / 菜谱 1.18）

### 2.8 离线收益（挂机核心）

```
offline_gain = min(elapsed_seconds, CAP) × 稳定产出速率 × 离线效率
```

- **CAP（上限）**：初始 8 小时，宿舍/酒窖可提升至 12/16 小时
- **离线效率**：初始 60%，可升级至 100%——保证在线收益永远优于离线，但不让离线无意义
- 结算时弹出「欢迎回来」摘要弹窗（获得金币/材料/经验/推层进度）
- **防时钟作弊**：保存 UTC 时间戳；加载时若 `now < last_saved_at`（时间回拨），按 0 处理该次离线并提示
- 离线期间菜肴烹饪计时照常推进（与受影响的产出保持一致）

### 2.9 转生系统（后置，MVP 不做）

- 「酒馆传承」：重置酒馆等级/材料/金币，**保留菜谱图鉴与 2 名指定冒险者**，获得传承点
- 传承点：每点全队产出 +2%，sqrt 衰减曲线（`points = floor((lifetime_earnings / scale)^0.5)`）
- 首次转生目标：核心循环完成后 30~90 分钟；二周目到达同进度应快 40~60%

### 2.10 留存节奏设计

- **5 分钟测试**：新玩家 5 分钟内必须做出第一个有意义决策（「先升级厨房还是先签约第二个冒险者」）
- 60 秒内可完成第一次签约；3 分钟内解锁第一道菜；10~15 分钟首次"碰墙"
- **回访时钟**（不同频率照顾不同玩家）：
  - 短时钟：菜肴出锅（15~30 分钟）
  - 中时钟：冒险者休整/日薪结算（2~5 小时）
  - 长时钟：离线收益 CAP（8 小时+）
- **反挂机悖论**：自动化不是终点。加入轻量主动点——酒馆随机事件（冒险者拼酒小游戏/流浪商人限时交易）、手动"开饭"按钮（立即触发 30 分钟菜肴增益）奖励回访

## 3. 技术方案

### 3.1 架构总览：三层分离

```
┌─────────────────────────────────────────────┐
│ 展示层  React 19 + Tailwind                  │
│   管理界面（酒馆/编队/菜谱/背包/图鉴）        │
│   + 战斗视口（PixiJS，Phase 2 引入，已确认）  │
├─────────────────────────────────────────────┤
│ 状态层  Zustand（细粒度 selector 订阅）       │
│   游戏状态唯一可信源，模拟层写入 → UI 响应    │
├─────────────────────────────────────────────┤
│ 模拟层  纯 TypeScript 无头引擎（headless）    │
│   固定步长 tick（1s）、战斗解算、掉落、        │
│   烹饪计时、忠诚度、经济——全部纯函数/可单测   │
├─────────────────────────────────────────────┤
│ 持久层  SaveAdapter 接口                      │
│   localStorage 起步 → 可切换 IndexedDB        │
│   版本化存档 + 链式迁移 + 导出/导入           │
└─────────────────────────────────────────────┘
```

关键原则：**模拟层不知道渲染，渲染层不知道规则**。战斗结算与离线快进复用同一套 tick 函数，保证离线结果与在线完全一致。

> 战斗画面（已确认后续要做）的形态：PixiJS 轻量视口——冒险者/魔物贴图对撞、攻击前倾微动效、飘字伤害数字、结算横幅。它**订阅模拟层事件回放**，不参与规则计算，因此可以随时后加而不动核心。

### 3.2 技术栈选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | **TypeScript**（strict） | 内容数据类型化（职业/魔物/菜谱为类型化常量），重构安全 |
| 构建 | **Vite** | 事实标准，HMR 秒级反馈 |
| UI | **React 19 + Tailwind CSS** | 挂机游戏 80% 界面是表格/列表/按钮，DOM 天然擅长 |
| 状态 | **Zustand**（+ subscribeWithSelector） | 细粒度订阅避免 1s tick 全页重渲染（参考 code-clicker 实践） |
| 场景渲染 | **PixiJS**（Phase 2 引入战斗视口；MVP 用纯 CSS/DOM 动效） | 渲染库仅 ~50KB gzip；本作战斗为数值模拟，不需要物理/场景管理等游戏框架负重 |
| 存档 | **localStorage 起步**，封装 `SaveAdapter` 接口 | 存档 <500KB 时够用；接口隔离便于切 IndexedDB（idb/localForage） |
| 测试 | **Vitest** | 模拟层纯函数天然可单测（战斗/掉落/离线/经济平衡脚本） |
| 部署 | Vite 静态构建 → **itch.io**（zip 上传）+ **GitHub Pages**（Actions 自动部署演示页） | 双渠道均零后端 |

#### 为什么不是 Phaser？

Phaser 3/4 是完整游戏框架（物理/输入/音频/场景管理，~345KB gzip），适合平台跳跃等"游戏感"强的项目。本作：

1. 战斗是数值结算，无需物理引擎
2. 界面 80% 是管理 UI，React/DOM 远比 Phaser UI 插件成熟
3. PixiJS 只做"战斗视口回放"这一件事，按需引入即可

已确认的"简单战斗画面"用 PixiJS 独立视口实现，架构不冲突；若后期想要更强的场景表现，可将视口升级为 Phaser canvas 嵌入 React。

### 3.3 存档系统（本地存储要点）

1. **版本化 + 链式迁移**：存档带 `version` 字段，迁移函数按版本链依次执行（v0→v1→v2…），旧档永不报废
2. **自动保存**：每 30s + `visibilitychange → hidden` 时保存（`beforeunload` 移动端不可靠，仅作兜底）
3. **导出/导入**：从 MVP 第一天就提供——JSON 文件下载/上传。本地存储是"租来的"（浏览器可清除、Safari 7 天未访问可回收），导出是玩家唯一的备份手段，也是换设备迁移方案
4. **持久化申请**：调用 `navigator.storage.persist()` 请求免驱逐；用 `navigator.storage.estimate()` 在设置页展示占用
5. **UTC 时间戳**：所有时间存 UTC，避免时区/夏令时问题
6. **数据结构分区**：`player`（进度）/ `roster`（冒险者）/ `inventory`（材料）/ `unlocks`（菜谱/图鉴）/ `settings` / `meta`（时间戳/游玩时长），便于按需加载和迁移

### 3.4 游戏循环与离线结算

```typescript
// 固定步长循环：模拟与渲染解耦
const TICK_MS = 1000;
let acc = 0;
function frame(now: number) {
  acc += now - lastFrame;
  while (acc >= TICK_MS) { engine.tick(1); acc -= TICK_MS; }
  lastFrame = now;
  requestAnimationFrame(frame);
}

// 离线结算： capped 快进
const elapsed = Math.min(now - lastSavedAt, OFFLINE_CAP_S);
const steps = elapsed; // 1s 步长
if (steps <= MAX_FAST_FORWARD_STEPS) {
  for (let i = 0; i < steps; i++) engine.tick(1);   // 精确回放
} else {
  engine.applyOfflineFormula(elapsed);               // 超长离线用闭式公式近似
}
showWelcomeBackModal(summary);
```

- 离线快进上限步数（如 57,600 步 = 16h）内用同循环精确结算（战斗/掉落/烹饪全一致）；超过则公式近似
- 页面隐藏（`visibilitychange`）时暂停 rAF，恢复时走同样的 catch-up——"欢迎回来"对切标签页也生效
- 模拟层战斗结算输出**事件流**（如 `hit/kill/drop/levelup`），MVP 阶段事件流只写日志，Phase 2 战斗视口直接订阅同一事件流做动画回放——这是后加战斗画面不动核心的关键设计

### 3.5 数据驱动内容

所有游戏内容（职业、魔物、菜谱、地牢层表、升级项、羁绊规则）集中放 `src/data/`，类型化常量或 JSON。新增一道菜 = 加一个数组元素，不改逻辑。数值平衡全部在数据文件里调，不碰引擎代码。

## 6. 开发路线图

### Phase 0 · 垂直原型（1~2 周）——验证核心循环

> 目标：一条完整但极小的"挂机链路"跑通，回答"这游戏好不好玩"。

- 1 个冒险者、1 层地牢、3 种魔物、2 种材料
- 1 道菜（材料→烹饪→buff 生效）
- 酒馆 1 个设施 5 级
- tick 引擎 + localStorage 存档 + 离线结算 + 欢迎回来弹窗
- 全部用占位色块/CC0 散图，无美术要求
- **验收标准**：关掉页面 1 小时再打开，能看懂发生了什么，且有"再挂一会"的冲动

### Phase 1 · MVP（3~6 周）——完整系统闭环

- 6 职业、5 人编队、前中后排 + 3 条羁绊
- 10 层地牢（1 个生态）、20+ 魔物
- 10 道菜谱、5 大酒馆设施
- 招募到访系统（稀有度权重）、忠诚度、日薪
- 存档导出/导入、`navigator.storage.persist()`
- 正式像素素材替换、数字格式化（K/M/B/T）
- **验收标准**：新玩家 5 分钟内做出第一个决策；2 小时内首次"碰墙"后仍有 3 个可选目标

### Phase 2 · 内容扩展 + 战斗画面（持续）

- **简单战斗画面（已确认）**：PixiJS 轻量视口——订阅模拟层事件流回放，贴图对撞 + 攻击前倾 + 伤害飘字 + 波次/结算横幅
- 2~3 个新地牢生态（每 10 层）、新菜系、酒窖饮品线
- 冒险者星级突破、酒馆随机事件（回访奖励）
- 成就/图鉴/统计页、（评估后）转生系统
- 移动端自适应布局打磨

### Phase 3 · 打磨发布（1~2 周）

- 音效/音乐接入、平衡终调（二周目速度应比一周目快 40~60%）
- PWA（可安装、离线可玩）
- **发布**：itch.io 上线（HTML5 zip）+ GitHub Pages 演示页（Actions 自动部署）
